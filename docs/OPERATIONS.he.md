# מדריך תפעול – Bake & Party

המסמך הזה מיועד למי שמנהלת את האתר ביום-יום ובפריסה. הסבר טכני כללי על הפרויקט נמצא ב-[README](../README.md).

## פריסה ועדכון האתר

1. השינויים נכנסים ל-GitHub (בדרך כלל דרך Pull Request ו-Merge לענף `main`).
2. Railway מפרסם אוטומטית אחרי כל עדכון של `main` (דקה-שתיים). בלשונית **Deployments** רואים **Active**.
3. אין צורך להריץ סקריפטים: טבלאות ועמודות חדשות נוצרות לבד בעליית השרת.
4. חיבורי משתמשים נשמרים במסד הנתונים, ולכן פרסום חדש לא מנתק אף אחד.

**חובה פעם אחת:** Volume קבוע ב-Railway עם Mount Path `/app/product_images`. בלעדיו תמונות שהועלו נמחקות בכל פרסום.
**גיבויים:** ראו "אבטחה וגיבויים" למטה.

## הגדרת שירותים חיצוניים

### מיילים (Brevo)
Railway חוסם שליחת מייל ב-SMTP (השגיאה `Network is unreachable`), ולכן שולחים דרך Brevo. חינם עד 300 מיילים ביום.
1. נרשמים ב-brevo.com ומאמתים טלפון.
2. **Settings ← Senders, domains, IPs ← Senders ← Add sender**, ומאמתים את כתובת השולח מהמייל שמגיע.
3. **Settings ← SMTP & API ← API Keys ← Generate a new API key**.
4. ב-Railway: `BREVO_API_KEY` = המפתח, `EMAIL_FROM` = הכתובת שאומתה.
5. בדיקה: פאנל הניהול ← **הודעות** ← "שליחה אליי לבדיקה", ואז **יומן שליחות**.

### התחברות עם Google
1. [Google Cloud Console](https://console.cloud.google.com) ← פרויקט חדש.
2. **APIs & Services ← OAuth consent screen**: External, שם האפליקציה "Bake & Party", מייל תמיכה. מפרסמים (Publish app).
3. **APIs & Services ← Credentials ← Create credentials ← OAuth client ID** ← סוג **Web application**.
4. ב-**Authorized JavaScript origins** מוסיפים: `https://www.bakeparty.co.il`, `https://bakeparty.co.il`.
5. מעתיקים את ה-**Client ID** (מסתיים ב-`.apps.googleusercontent.com`) ל-`GOOGLE_CLIENT_ID` ב-Railway.

אחרי זה מופיע בחלון ההתחברות כפתור "המשך עם Google", והביקורות מציגות את תמונת הפרופיל מ-Google.

### התראות לטלפון (Web Push)
`python tools/gen_vapid.py` במחשב, ואת שני הערכים מדביקים ב-Railway. באייפון התראות עובדות רק אחרי "הוספה למסך הבית".

### גוגל (SEO)
- Search Console: מוסיפים נכס מסוג "קידומת כתובת URL", מאמתים בתג HTML (`GOOGLE_SITE_VERIFICATION`), ושולחים את `sitemap.xml`.
- פרופיל העסק בגוגל: כתובת, שעות וקישור לאתר זהים לאתר.

## אבטחה וגיבויים

### אימות דו-שלבי (מומלץ מאוד לחשבון המנהלת)
1. פאנל הניהול ← **צוות ומשתמשים** ← **🔐 אימות דו-שלבי** ← **הפעלה**.
2. מתקינים בטלפון **Google Authenticator** וסורקים את קוד ה-QR.
3. מקלידים את הקוד בן 6 הספרות ← **אישור והפעלה**.
4. מופיעים 8 **קודי גיבוי**. שומרים אותם במקום בטוח (הדפסה / צילום מסך). כל קוד עובד פעם אחת, למקרה שהטלפון אבד.

מעכשיו בכניסה מבקשים גם קוד מהאפליקציה (גם בכניסה עם Google). עובד/ת שאיבד/ה את הטלפון: מנהלת לוחצת "איפוס סיסמה" על המשתמש, וזה מכבה גם את האימות הדו-שלבי.

### שכחתי סיסמה
בחלון ההתחברות יש קישור **"שכחתי סיסמה"**. נשלח מייל עם קישור שתקף 30 דקות ועובד פעם אחת. אחרי בחירת סיסמה חדשה כל המכשירים האחרים מתנתקים. דורש שהמיילים (Brevo) מוגדרים.

### גיבויים
- **אוטומטי:** פעם בשבוע כל מנהלת מקבלת מייל "💾 גיבוי שבועי" עם קובץ zip של כל הנתונים. שומרים אותו ב-Google Drive.
- **ידני:** פאנל ← **צוות ומשתמשים** ← **💾 גיבוי** ← "הורדת גיבוי מלא".
- בקובץ אין סיסמאות גלויות (רק מוצפנות), ואין בו חיבורים פעילים או מפתחות של אימות דו-שלבי.
- **בנוסף, אם יש:** ב-Railway, בשירות של Postgres ← **Backups**, אפשר להפעיל גיבוי אוטומטי של כל מסד הנתונים (תלוי בתוכנית של Railway).

### הגנות נוספות שפועלות לבד
- **CSP:** הדפדפן טוען סקריפטים רק מהאתר עצמו ומ-Google (התחברות). אם משהו מפסיק לעבוד אחרי שינוי, אפשר זמנית לשים `CSP_REPORT_ONLY=1`.
- **הגבלת דומיינים (CORS):** רק האתר שלנו יכול לפנות לשרת מתוך דפדפן.
- **HTTPS קבוע (HSTS)**, נעילת חשבון אחרי ניסיונות כושלים, והגבלת קצב לכל פעולה רגישה.

## עבודה יומיומית

### הזמנות (staff.html)
- הזמנה חדשה מופיעה תוך 20 שניות, עם צליל (אחרי "הפעלת צליל") והתראה בטלפון (אחרי "התראות בטלפון על הזמנות").
- שלבים: **התחלתי להכין ← מוכנה לאיסוף** (הלקוח מקבל מייל/התראה) **← נאספה ושולמה**.
- **"חסר?"** מסמן פריט חסר. הלקוח מקבל הודעה ובוחר בעצמו מוצר אחר, להמשיך בלעדיו או לבטל. התשובה מופיעה על כרטיס ההזמנה.
- **"💬 וואטסאפ ללקוח"** פותח הודעה מוכנה עם קישור המעקב.
- המתג **"מקבלים הזמנות באתר"** סוגר הזמנות זמנית.

### ביקורות (פאנל ← ⭐ ביקורות)
ביקורות נכתבות רק מחשבון (כולל Google) ומופיעות רק אחרי אישור. אפשר להסתיר, למחוק ולהגיב בשם החנות. תגובות של לקוחות מופיעות מיד ואפשר למחוק אותן.

### מוצרים ווולט (פאנל ← מוצרים)
- **ייבוא מאקסל של וולט:** תצוגה מקדימה ואז אישור. רק מוסיף, לא מוחק. המחיר באתר = מחיר וולט חלקי 1.3, מעוגל ל-x.9.
- **השוואת מלאי מול וולט:** מציעה מה לסמן כאזל / להחזיר למלאי, ומה קיים בוולט וחסר באתר.
- עריכת מוצר: מהאתר עצמו כשמחוברים כמנהלת (לחיצה על מוצר).

### קליטת חשבונית מספק (פאנל ← מוצרים ← 🧾)
1. מעלים PDF או צילום של החשבונית (גם כמה עמודים). ה-AI קורא כל שורה: ברקוד, מק"ט, כמות, מחיר, הנחה.
2. **מחיר ספק ליחידה** = המחיר שמודפס בעמודת "מחיר", בלי מע"מ ו**לפני** הנחות. ההנחות שהספק נותן (בשורה או על כל החשבונית) לא יורדות מהחישוב.
3. **מחיר באתר** = מחיר ספק × 2 + 1.90, מעוגל למעלה ל-.00 / .50 / .90. **בוולט** = מחיר האתר + 30%, אותו עיגול.
4. כל שורה מותאמת למוצר באתר: לפי ברקוד, אחר כך מק"ט של הספק, ורק אז לפי שם (בהתאמה כמעט ודאית בלבד).
   כשאין התאמה בטוחה, השורה מוצעת כ"מוצר חדש" ומוצגים מוצרים דומים לבחירה ידנית.
5. מסך האישור מראה כל שינוי מחיר (▲ / ▼). שורה מסומנת באדום כשהמחיר שנקרא לא מתאים לסה"כ שבחשבונית (אחרי שמחזירים את ההנחה), ובכתום כשה-AI לא בטוח.
6. **שום דבר לא משתנה עד "אישור ושמירה"**, והכל נשמר יחד או לא בכלל. חשבונית שכבר נקלטה לא תיקלט פעמיים.
7. מוצרים חדשים נכנסים במלאי, ומופיעה רשימה של מוצרים שצריך לצלם.

שימו לב לבלונים ופריטים "/100 יח'": ה-AI מסמן לבדוק אם מוכרים יחידה או שקית.

### תמונות מוצרים
- **צילום בטלפון:** בעריכת מוצר ← "📷 החלפת תמונה". התמונה מסודרת אוטומטית: רקע לבן, מוצר במרכז, יישור קופסאות עקומות, תיקון תאורה. אם לא אהבתם: "להשתמש בתמונה המקורית".
  נשמרת גם גרסה רחבה (16:9) לוולט. הפעם הראשונה אחרי פריסה איטית יותר (טעינת מודל של ~180MB).
- **🔍 הצעות תמונה:** לפי הברקוד, ממאגר Open Food Facts (בעיקר מוצרי מזון). התמונות שם ברישיון CC BY-SA, ולכן מתחת לתמונה מופיע קרדיט, וזה חובה.
- **קישור לתמונה:** אפשר להדביק קישור ישיר לתמונה מאתר הספק. השתמשו רק בתמונות שמותר לכם (ספקים בדרך כלל מרשים לחנויות שמוכרות את המוצר). לא להעתיק תמונות סתם מגוגל.

### חיבור ישיר לוולט (API)
- כתובות שנמסרו לוולט:
  - Redirect URL: `https://www.bakeparty.co.il/api/wolt/oauth/callback`
  - Webhook להזמנות: `https://www.bakeparty.co.il/api/wolt/webhook/orders`
- ב-Railway: `WOLT_CLIENT_ID`, `WOLT_CLIENT_SECRET`, `WOLT_ENV=development` (בזמן הבדיקות), ו-`WOLT_WEBHOOK_SECRET` (רק אחרי שאותו ערך נמסר לוולט, אחרת ההזמנות שלהם יידחו).
- פאנל ← מוצרים ← **חיבור לוולט** ← מתחברים בוולט ובוחרים את החנות. מזהה החנות בוולט נקרא אוטומטית.
- הטוקנים מתחדשים לבד, גם פעם בשבוע כשאין פעילות (אחרת אחרי 30 יום החיבור מת). אם וולט דוחים חידוש, הכרטיס מראה "החיבור פג" ומחברים מחדש.
- הזמנות מוולט נשמרות פעם אחת גם אם וולט שולחים שוב (עד 4 ניסיונות ב-15 שניות), ומופיעות במסך הצוות בכרטיס "🛵 הזמנות וולט".
  בסביבת הבדיקות יש שם כפתורי אישור / מוכנה / דחייה (במקום האייפד). בחנות האמיתית מאשרים באייפד של וולט.
- **מחיר ומלאי לוולט:** כל שינוי מחיר או מלאי באתר (עריכה, חשבונית, "אזל" במסך הצוות, ייבוא) נכנס לתור ונשלח לוולט לבד.
  - מחיר בוולט = מחיר באתר + 30%, מעוגל למעלה ל-.00 / .50 / .90.
  - וולט מאפשרים עדכון אחד כל 15 דקות (או מה שמוגדר לחנות), אז השינויים נאספים ונשלחים יחד.
  - ההתאמה היא לפי **SKU = מספר המוצר באתר** (רואים אותו בכתובת: `#p=939`). מוצר בוולט בלי SKU כזה לא מתעדכן.
  - בפעם הראשונה: פאנל ← מוצרים ← כרטיס וולט ← "שליחת כל המוצרים לוולט" (נשלח במנות של 500).
  - מבצעים של האתר לא נשלחים לוולט.
  - מוצר שנמחק באתר מסומן בוולט כלא זמין. מוצר חדש, תמונה ושם **לא** עוברים לוולט: מוסיפים/משנים גם בעורך התפריט של וולט, עם SKU = מספר המוצר באתר.
- **ייצוא מוצרים חדשים לוולט** (כרטיס וולט ← 📦): קובץ ZIP עם אקסל של כל המוצרים שיש באתר ואין בוולט (כולל SKU ומחיר לוולט) ותיקיית `images` עם תמונה לכל מוצר בשם `<sku>.jpg`, בפורמט של וולט (רקע לבן, 16:9). שולחים את ה-ZIP לוולט. מה כבר יש בוולט נלקח מבדיקת התפריט האחרונה, או מקובץ ייצוא שמעלים.
- **בדיקת התפריט בוולט** (כרטיס וולט ← 🔎): האתר קורא את התפריט מוולט, מסמן SKU חשודים (שם או מחיר שלא מתאימים למוצר באתר) ומכין קובץ השלמה למוצרים בלי SKU. אפשר להריץ בערך פעם ברבע שעה.

### צוות, שעות ושכר
- **צוות ומשתמשים:** הוספת עובד/ת יוצרת סיסמה זמנית, שמוחלפת בכניסה הראשונה. השבתה מנתקת מיד. תמיד נשאר לפחות מנהל/ת פעיל/ה אחד/ת.
- **שעות ושכר:** תעריף לכל עובד/ת, תיקון והוספת משמרות. כל שינוי נרשם ביומן הפעולות.

### הודעות ויומן שליחות (פאנל ← הודעות)
שליחת הודעה ללקוחות שאישרו קבלת עדכונים, ו**יומן שליחות** שמראה כל מייל והתראה, האם יצאו, ואם לא, למה.

## עבודה מקומית (למפתחת)

```bash
docker compose -f local-dev/docker-compose.yml up -d
pip install -r requirements.txt
python tools/import_data.py data/wolt-export-2026-08-24.xlsx   # נתוני דוגמה (מוחק ובונה מחדש את טבלאות המוצרים)
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD=changeme123 uvicorn main:app --reload
```
האתר עולה ב-`http://localhost:8000`, הפאנל ב-`/admin.html` ומסך הצוות ב-`/staff.html`.
